# 06. 행정과 치안

## 1. 요청함

`Request { id, type, citizen, household, payload, createdDay, deadlineDay, status, handledBy }`
`status`: `PENDING` → `ACCEPTED` | `REJECTED` | `EXPIRED`

- 같은 주민의 같은 종류 요청은 한 번에 하나만 대기한다.
- 기한은 `§request.deadline_days`. 지나면 `EXPIRED` 이고 효과는 반려와 같다.
- 수락·반려는 `requestScore` 를 ±5 움직인다(`02-citizens.md` 4절 신뢰).

| type | 올리는 조건 | payload | 수락하려면 | 반려·만료의 효과 |
|---|---|---|---|---|
| `JOB` | 무직 성인의 희망 직업이 정해짐(`04-jobs.md` 9절) | 직업 id | 빈자리 있는 작업구역을 골라 배정한다. 다른 직업의 구역이어도 된다 | 성취 계속 하락. `§request.retry_days` 뒤 다시 올림 |
| `JOB_CHANGE` | `04-jobs.md` 9절 | 직업 id | 새 구역에 배정 | 쿨다운, 성취 −10 |
| `HOUSING` | 무주택, 또는 주거 < 40 인데 살 집을 못 구함 | 가구원 수 | 침대가 맞는 빈 시 소유 집에 임대로 배정 | 주거 계속 낮음. 무단 점유 후보 |
| `SUPPLY` | 필수품을 `§request.supply_days` 일째 못 구함. 허기 0이 2일 이어지면 음식 요청이 바로 올라간다(아사 위험). 종류: 음식, 도구, 가축, 씨앗, 수납함, 침대 | 품목, 수량 | 그 주민에게 건네거나, 금고 판매 목록이나 시 판매함에 내놓거나, 그 사이에 스스로 구하면 자동 수락 | 해당 욕구 계속 하락 |
| `REPORT` | `05-crime.md` 3절 | 사건 id | 경비병을 수사에 배정 | 사건이 바로 `COLD`. 신고자 안전 −5 |
| `DEMAND` | 집단 행동의 요구 | 요구 종류 | `05-crime.md` 6절 표의 조건을 채움 | 집단 행동 격화 |
| `GUARDIAN` | 보호자 없는 미성년 | | 맡을 가구를 지정 | 금고의 지원금이 계속 나감 |
| `MINE_SITE` | 광산이 거의 소진됨 | 광산 구역 | 새 광산 구역을 칠하고 광부를 옮김 | 광산이 닫히면 광부가 무직이 됨 |
| `INFORMANT` | 잡힌 조직원의 밀고 제안 | 사건 id | 그 주민의 처벌을 한 단계 낮춤 → 조직 명단 공개 | 없음 |

- 시장은 요청과 상관없이 주민에게 물건과 돈을 직접 건넬 수 있다. 받은 날 그 주민의 `requestScore` +2 (하루 한 번).

## 2. 공직 임명

- 권한 `APPOINT`. 성인 주민을 경비병이나 부관으로 임명한다. 원래 직업과 사물함은 내려놓는다.
- 인원 상한은 시 레벨(5절).
- 봉급은 매일 금고에서 나간다(`03-economy.md` 8절). 해임하면 무직이 된다.
- 공직자도 가구·욕구·성향·범죄 판단이 보통 주민과 같다.

## 3. 경비대

### 임무
한 번에 하나만 한다. 시장이나 행정 부관이 정한다.

| 임무 | 내용 |
|---|---|
| `PATROL` | 광장 → 초소 → 각 구역 중심을 도는 순찰. 기본 임무 |
| `INVESTIGATE` | 사건 하나의 수사(`05-crime.md` 3절). 풀리거나 미제가 되면 순찰로 돌아간다 |
| `AUDIT` | 가구·광산 조합·부관 하나에 대한 감사. `§audit.days` 일 |
| `ENFORCE` | 판결 집행(6절): 체포, 벌금 징수, 압류, 퇴거, 추방, 처형 |
| `SUPPRESS` | 집단 행동 하나의 진압 |

- **방어는 임무가 아니라 끼어들기다.** 어느 임무 중이든 몬스터가 주민 16블록 안에 오면 싸우고, 끝나면 하던 일로 돌아간다.
- 순찰 중인 경비병의 `§guard.night_share` 는 밤에 순찰하고 오전에 잔다.

```
순찰 밀도 = min(1, 매수 안 된 PATROL 경비병 수 ÷ max(1, 관리 청크 수 ÷ §guard.chunks_per_guard))
```

- **현행범:** 경비병이 범죄를 목격하면 그 사건은 `evidence` 1로 열리고, 그 경비병이 바로 체포를 시도한다.
- **체포:** 대상에게 걸어가 감옥 구역까지 데려간다(대상이 경비병을 따라 걷는다). 대상의 폭력성 ≥ 70 이면 저항해서 싸운다. 조직 세력이 경비 전력을 넘으면 `05-crime.md` 8절의 실패 규칙을 따른다.
- **장비:** 검이 필수 도구다. 다른 직업의 도구처럼 자기 돈으로 사고, 시장이 건네줘도 된다. 갑옷과 활은 있으면 쓴다.
- 경비병의 숙련은 수사·감사·전투를 한 번 할 때마다 오른다. 속도 배수는 직업 숙련 표와 같다.

### 구역
- **초소 `post`:** 순찰 경유지. 초소가 없어도 경비병은 일한다.
- **감옥 `jail`:** 정원은 구역 안 침대 수. 감옥이 없거나 꽉 차면 구금형을 내릴 수 없다. 구금된 주민의 식비는 금고가 낸다(하루 `§jail.food_cost` × P).

## 4. 부관

보직은 임명할 때 정하고 나중에 바꿀 수 있다. 숙련은 보직별로 따로 쌓인다(직업 숙련 표의 경험치 기준을 쓴다).

### 행정 부관 (`ADMIN`)
- 작업 구간에 광장에 있어야 일한다.
- 결산 10단계에서 규칙(다음 절)에 따라 대기 중인 요청과 사건을 처리한다. 하루 처리량 = `§aide.capacity_base` + 2 × (숙련 − 1). 부관이 여럿이면 합친다.
- 처리 한 건에 경험치 2.
- 부관 한 명마다 도시의 관리 청크 상한이 `§aide.chunks_bonus` 늘어난다(보직 무관).
- 부관이 한 일은 처리 기록에 남는다: 무엇을, 어느 규칙으로.

### 정보 부관 (`INTEL`)
- 시장이 감시 대상 가구를 고른다. 한 번에 2 × 숙련 + 1 가구.
- 결산 10단계에서 보고를 갱신한다. 숫자 정보에는 ±(25 − 5 × 숙련)%의 오차가 붙는다.
- 보고 한 번에 경험치 1.

| 숙련 | 열리는 정보 | 범위 |
|---|---|---|
| 1 | 정확한 행복도, 욕구 9개, 불만 원인 1위 | 감시 대상 |
| 2 | 경제 태도 5개, 선호 직업, 실제 순소득 추정, 지출 | 감시 대상 |
| 3 | 기질 4개(낮음·중간·높음), 그 가구가 아는 소문 | 감시 대상 |
| 3 | 소문별로 아는 주민의 수 | 도시 전체 |
| 4 | 형성 중인 집단 행동(주동자, 인원), 신고 안 된 사건, 횡령 의심 | 도시 전체 |
| 5 | 조직의 존재, 의심 명단, 매수가 의심되는 공직자 | 도시 전체 |

- 숙련 5의 의심 명단: 진짜 구성원 각각이 70% 확률로 오르고, 구성원이 아닌 주민이 10% 섞인다.

### 매수된 부관
- 행정: 조직원이 올린 요청은 규칙과 상관없이 수락한다. 조직 사건의 신고는 "조치 없음"으로 닫는다. 처리 기록에는 규칙대로 한 것으로 적는다.
- 정보: 조직에 관한 정보를 보고에서 뺀다.
- 드러내는 법: 경비병에게 그 부관의 감사를 맡긴다(발각 확률 `§audit.base`). 또는 처리 기록을 실제 배정·사건 상태와 직접 대조한다(기록은 "반려"인데 실제로는 배정돼 있다).

## 5. 규칙

`Rule { id, order, enabled, trigger, conditions[], action, params }`

- `trigger`: `REQUEST`(요청이 대기 중일 때), `CASE`(사건 상태가 바뀔 때), `DAILY`(결산마다 한 번).
- `conditions` 는 전부 맞아야 한다(AND). OR이 필요하면 규칙을 둘로 나눈다.
- `REQUEST`·`CASE` 는 위에서부터 처음 맞는 규칙 하나만 적용한다. 맞는 규칙이 없으면 시장을 기다린다. `DAILY` 는 맞는 규칙을 전부 한 번씩 실행한다.
- 규칙 줄 수 상한은 시 레벨.

### 조건
| 조건 | 인자 |
|---|---|
| `request.type` | 종류 |
| `request.job` | 직업 id |
| `citizen.job`, `citizen.job_family` | |
| `citizen.arrears_weeks >=` | 수 |
| `citizen.has_record` | 참/거짓 |
| `citizen.housing` | `OWNER`, `TENANT`, `HOMELESS`, `SQUATTER` |
| `job.workers <=`, `job.vacancies >=` | 직업 id, 수 |
| `case.type`, `case.tier >=`, `case.evidence >=`, `case.has_suspect` | |
| `city.treasury >=`, `<=` | 금액 |
| `city.price_index >=`, `<=` | 값 |
| `city.item_price >=`, `<=` | 품목, 기준값 대비 배수 |
| `city.item_stock <=` | 품목, 수 |
| `city.vacant_homes >=` | 수 |
| `city.unemployed >=` | 수 |
| `city.starving >=` | 가구 수 |
| `city.starve_risk >=` | 허기 0이 2일 넘게 이어진 주민 수 |
| `city.vault_free <=` | 금고 창고의 빈 칸 수 |
| `city.purchase_spend >=` | 오늘의 시 수매 지출 |
| `city.solve_rate <=` | 0~1 |
| `guards.idle >=` | 순찰 중인 수 |

### 행동
| 행동 | 내용 |
|---|---|
| `accept` | 요청 수락. `JOB`·`JOB_CHANGE` 는 그 직업의 빈자리 구역 중 종사자가 가장 적은 곳에, `HOUSING` 은 침대가 맞는 빈 시 소유 집 중 임대료가 가장 싼 곳에 배정 |
| `reject` | 요청 반려 |
| `assign_guard` | 순찰 중인 경비병 한 명을 그 사건의 수사나 그 가구의 감사에 배정 |
| `set_duty` | 경비병 n명의 임무를 바꿈 |
| `judge` | 사건에 기본 처벌(`05-crime.md` 5절)을 내림. 벌금·배상·압류·구금까지만 |
| `dun` | 체납 가구에 독촉 |
| `seize` | 체납 가구에 압류 |
| `buy` | 금고 돈으로 품목을 상한가 이하에서 n개까지 사서 금고 창고에 넣음 |
| `order` | 주문 생산 품목을 n개 발주하고, 완성되면 받아서 금고 창고에 넣음 |
| `give` | 금고 창고의 품목을 조건에 맞는 가구에 n개씩 건넴 |
| `set_sale_price` | 금고 판매 목록의 품목 값을 정함 |
| `set_purchase` | 시 수매를 켜거나 끄고 하루 예산을 정함 |

- **부관이 못 하는 것(D-23):** 구역을 새로 칠하기, 발행, 세율·임대료·금지 품목 변경, 추방, 처형, 임명·해임, 규칙 편집.
- `buy`, `order`, `give` 는 부관이 실제로 걸어가서 사고 건넨다. 물건의 출납은 금고에서 하고, 이때 부관이 금고 문을 연다. 추상 처리 경로가 있다.
- 자동 발행(`purchase.autoIssue`)을 켜고 끄는 것은 발행 권한이므로 규칙으로 못 한다.

## 6. 처벌의 집행

판결(`Judge`)은 사건에 처벌을 붙이는 것이고, 경비병이 `ENFORCE` 로 집행한다.

| 처벌 | 집행 | 조건 |
|---|---|---|
| 훈방 | 사건을 닫는다 | |
| 벌금 | 그 가구 지갑에서 금고로(`FINE`). 모자란 만큼은 체납액에 더한다 | |
| 배상 | 그 가구 지갑에서 피해 가구로(`COMPENSATION`). 장물이 남아 있으면 물건을 돌려준다 | |
| 압류·몰수 | 경비병이 그 가구 컨테이너에서 정한 값어치를 꺼내 금고 창고(금고가 없으면 광장 구역의 사물함)로 옮긴다. 주택 몰수는 소유를 시로 돌린다 | |
| 구금 | 감옥으로 데려가 정한 날수 동안 둔다. 일하지 못한다 | 감옥에 빈 침대 |
| 추방 | 주민이 도시 경계까지 걸어가 사라진다. 명부에서 지운다. 재산은 상속 규칙대로(가구에 남은 사람 → 자녀 → 금고) | 시장만 |
| 처형 | 경비병이 감옥이나 광장에서 집행한다. 판결이 붙은 주민을 시장이 직접 죽여도 처형으로 친다 | 시장만 |

- 판결은 집행 전까지 취소할 수 있다. 구금은 중간에 풀어 줄 수 있다.

### 처벌이 주민에게 주는 영향
| | `evidence` ≥ 0.5 (정당) | `evidence` < 0.5 (증거 없음) |
|---|---|---|
| 벌금·배상 | 그 가구 신뢰 −10 | 7절의 "증거 없는 처벌(경)" |
| 압류·구금 | 그 가구 신뢰 −20 | 7절의 "증거 없는 처벌(경)" |
| 추방·처형 | 그 가구와 부모·자녀·배우자의 신뢰 −15 | 7절의 "증거 없는 처벌(중)" |
| 집행을 본 주민 | 안전 +5, 불온성 −3. 처형이면 신뢰 −5 가 더해진다 | 목격자가 된다(소문) |

## 7. 시장의 범죄와 소문

시장과 의원(이하 시정부)의 행위에만 적용한다. 처벌은 없고 소문이 된다.

### 무엇이 범죄인가
| kind | 판정 | 심각도 |
|---|---|---|
| `MURDER` | 플레이어의 직접 공격(근접, 투사체)으로 주민이 죽음. 처형 판결이 붙어 있으면 제외 | `§rumor.sev_murder` |
| `UNJUST_MAJOR` | `evidence` < 0.5 인 추방·처형 | `§rumor.sev_unjust_major` |
| `ASSAULT` | 플레이어의 직접 공격으로 주민이 다침. 주민당 하루 한 번 | `§rumor.sev_assault` |
| `THEFT` | `HOME`·`WORK`·`MINE_COOP` 컨테이너에서 아이템을 꺼냄, 또는 그 컨테이너를 부숨. 압류 판결이 붙은 가구의 것은 제외. 컨테이너당 하루 한 번 | `§rumor.sev_theft` |
| `PROPERTY` | 가구 소유 거주구역 안의 블록을 부숨. 구역당 하루 한 번 | `§rumor.sev_property` |
| `UNJUST_MINOR` | `evidence` < 0.5 인 벌금·배상·압류·구금 | `§rumor.sev_unjust_minor` |

- **범죄가 아닌 것:** 컨테이너를 열어 보기, 물건을 넣기, 블록을 놓기, 시 소유 구역의 블록을 부수기, 용암·낙하·몬스터 유인 같은 간접 살해(사고사로 기록되고, 이웃의 안전이 그날 −5).
- 누명(`FALSE_SOLVED`)으로 내린 처벌은 진실이 드러나는 날 `UNJUST_…` 로 소급된다.

### 목격
- `05-crime.md` 3절의 목격 규칙을 쓴다. 플레이어의 교활함* 은 0으로 친다. 웅크리면 × 0.7, 투명화 효과면 0.
- 살아남은 피해자는 목격자다. 절취는 주인이 그 자리에 없으면 목격자가 아니다.
- **목격자가 없으면 소문이 생기지 않는다.**
  - 절취·파손: 범인 모를 보통 사건으로 접수된다. 진범이 시정부라서 수사는 반드시 실패하고 미제가 된다(안전 욕구를 깎는다).
  - 살해: 실종으로 기록된다. 가족의 가족 욕구만 깎인다.

### 소문
`Rumor { id, kind, severity, day, victimHousehold, knowers, hushed }`

- 생길 때 `knowers` = 목격자.
- **듣는 순간(주민당 소문당 한 번):** 신뢰 −심각도, 안전 −심각도 ÷ 2, 불온성 + 심각도 × `§traits.sub_rumor_k`. 피해자와 같은 가구이거나 부모·자녀·배우자면 신뢰 타격이 2배다.
- **전파:** 만남(`02-citizens.md` 6절)마다, 한쪽만 아는 소문 각각에 대해 `§rumor.spread_base` × (0.5 + 말하는 쪽 조직성 ÷ 100) 의 확률로 옮는다. 입막음된 주민은 옮기지 않는다. 비방 벽보도 옮긴다.
- **소멸:** `§rumor.lifetime_days` 뒤 지운다. 신뢰는 목표값 쪽으로 서서히 돌아온다.
- 아는 주민이 늘수록 도시 평균 행복도가 내려간다. 따로 도시 단위 벌점은 두지 않는다.

### 수습
| 수단 | 조건 | 효과 |
|---|---|---|
| 배상 | 피해 가구에 `심각도 × §rumor.comp_per_sev × P` 이상을 준다(금고) | 심각도가 절반이 된다. 이미 들은 주민은 깎였던 신뢰의 절반을 돌려받는다. 소문당 한 번 |
| 입막음 | 아는 주민 한 명에게 `심각도 × §rumor.hush_per_sev × P` 이상을 준다(`HUSH`) | 불온성 < 60: 그 주민은 옮기지 않는다. 불온성 ≥ 60: 돈은 받고, 50% 확률로 그대로 옮기며 다음에는 두 배를 요구한다 |
| 목격자 제거 | | 그 자체가 또 범죄다 |
| 기다림 | | 소멸까지 범죄와 집단 행동의 압력이 높다 |

### 시정부가 아닌 플레이어
- 위의 행위를 하면 주민의 범죄와 같은 사건이 된다. 목격되면 용의자가 그 플레이어다.
- 목격된 무게 3 이상의 범죄: 경비병이 `§outsider.hostile_days` 동안 그 플레이어를 보면 공격한다.

## 8. 시 레벨

성인과 미성년을 합친 인구로 정한다. 결산 12단계에서 갱신한다. 인구가 줄어도 레벨은 내려가지 않는다.

| 레벨 | 인구 | 인구 상한 | 관리 청크 | 경비병 | 부관 | 규칙 줄 |
|---|---|---|---|---|---|---|
| 1 | 0~9 | 12 | 9 | 2 | 0 | 0 |
| 2 | 10~24 | 30 | 16 | 4 | 1 | 6 |
| 3 | 25~49 | 60 | 25 | 8 | 2 | 12 |
| 4 | 50~99 | 120 | 36 | 14 | 3 | 24 |
| 5 | 100 이상 | `§perf.max_citizens` | 49 | 24 | 4 | 48 |

- 관리 청크 상한 = 표의 값 + 부관 수 × `§aide.chunks_bonus`. 부관이 줄어 상한을 넘게 되면 청크는 그대로 두고 더 늘리지만 못 한다.
- 표의 값은 데이터 `city_levels.json` 에서 읽는다.

## 9. 의회

- 시장이 도시 패널의 의회 탭에서 플레이어를 의원으로 올리고 권한을 항목별로 준다(`01-architecture.md` 10절).
- 금고, 신뢰, 소문은 도시에 하나다. 의원의 범죄도 시정부의 범죄다.
- 표결은 없다.
- 시장이 서버를 떠나도 도시는 남는다. 시장 자리를 넘기는 기능은 두지 않는다(운영자 명령으로만).
