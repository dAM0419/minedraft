## 불변식

코드가 어느 단계에서든 지켜야 하는 규칙이다. 테스트로 검사한다.

1. **돈은 발행으로만 생기고 저절로 사라지지 않는다.** 모든 지갑 + 금고 + 세상에 있는 동화 아이템의 합 = 발행 누계. 돈의 이동은 `Ledger.transfer(from, to, amount, reason)` 하나로만 한다.
2. **아이템은 복제되거나 사라지지 않는다.** 거래는 컨테이너와 인벤토리 사이의 실제 이동이다. 예외는 레시피에 따른 생산과 소비, 도구 내구도 소모뿐이다.
3. **진실은 서버에만 있다.** 기질, 실제 소득, 진짜 범인, 조직 명단, 범죄 숙련은 어떤 패킷에도 싣지 않는다. 클라이언트로 가는 자료형은 공개 필드만 가진 별도 타입이다.
4. **판단은 명부에서, 실행은 엔티티가.** 주민의 결정은 `CitizenRecord` 와 도시 데이터만으로 내린다. 엔티티는 정해진 행동을 월드에서 수행한다.
5. **결산은 정해진 순서로, 재현 가능하게 돈다.** 난수는 `hash(도시 시드, 도시 날짜, 단계 번호)` 로 만든 생성기만 쓴다.
6. **행동에는 추상 처리 경로가 있다.** 엔티티가 실행 창 안에 못 한 행동(밤을 건너뜀, 길이 막힘)은 다음 결산에서 같은 규칙으로 결과만 낸다. 추상 처리된 범죄에는 목격자가 없다.
7. **도시가 꺼져 있으면 아무것도 진행되지 않는다.** 도시 날짜, 수명, 세금 주기, 소문 회복이 모두 멈춘다.
8. **수치는 설정에서, 직업·범죄·품목은 데이터에서 읽는다.** 코드에 숫자와 품목 id를 박지 않는다.
9. **플레이어의 모든 조작은 권한 검사를 거친다.** `CityPermission` 없이 도시 상태를 바꾸는 패킷 처리는 없다.
10. **주민 한 명의 실패가 도시를 멈추지 않는다.** 작업·구매·범죄 한 건이 예외를 던지면 그 건만 취소하고 기록한다.

## 결정 로그

2026-11-16에 정한 것이다. "근거"가 시뮬이면 `03-economy.md` 의 시뮬레이션 절을 본다.

| 번호 | 결정 | 근거 |
|---|---|---|
| D-01 | 주민은 바닐라 주민에 데이터를 붙이지 않고 **별도 엔티티** `citizen` 으로 만든다. 영입 때 바닐라 주민을 바꿔치기한다 | 바닐라 주민의 두뇌(직업 블록 점유, 번식, 거래, 소문)가 CaG의 모든 판단과 충돌한다 |
| D-02 | 구역 태그는 **그룹 하나**(`civilizeandgovern:zone`)에 다 넣는다. 한 칸에는 구역 하나만 | 그룹 안 배타 규칙으로 구역 겹침을 막는다. DaB 태그와는 그룹이 달라 겹칠 수 있다 |
| D-03 | 구역은 바닥만 칠해도 된다. 칠한 칸과 그 위 `§zone.headroom` 칸까지 구역 안으로 본다 | 편집 부담 |
| D-04 | 가게 구역은 **상인 전용**이다. 다른 생산자는 자기 작업구역의 사물함에서 판다(D-45) | 상인이 없는 초기에도 시장이 돌아야 한다 |
| D-05 | 물건의 주인은 **컨테이너의 주인**으로 정한다. 컨테이너마다 가구 하나가 주인이다 | 아이템마다 주인 표시를 달지 않기 위해 |
| D-06 | 화폐는 정수 한 종류. 아이템은 1·10·100 세 단위. 빵 기준값 12 | 5% 조정이 정수에서 의미를 가지려면 값이 충분히 커야 한다 |
| D-07 | 호가 규칙: 재고가 목표의 절반보다 적으면 +5%, 1.5배보다 많으면 −5%, 그 사이면 기준 쪽으로 2.5%씩. D-37로 배수 방식이 됨 | 시뮬. "품절일 때만 인상"은 통화량이 5배가 돼도 물가가 안 움직였다 |
| D-08 | **물가 기준선 P** 를 둔다. 가구가 가진 돈의 1인당 값을 기준값으로 나눈 것의 14일 평활. 평균이 아니라 중앙값(D-39) | 시뮬. 이것이 있어야 발행이 물가로 이어진다 |
| D-09 | 가격 하한 = max(재료비 × 1.05, 기준가 × 0.5 × P). 상한은 D-37 | 시뮬. 하한이 없으면 수요가 고정된 필수품 값이 바닥까지 떨어진다 |
| D-10 | 1차 생산자도 팔 재고가 목표의 2배를 넘으면 그 품목 작업을 쉰다 | 시뮬. 안 그러면 밀 수백 개가 쌓인다 |
| D-11 | 가구 예산은 **식량을 가장 먼저** 떼어 둔다. 재료 구매보다 앞이다 | 시뮬. 재료를 먼저 사면 장인이 굶는다 |
| D-12 | ~~굶어도 죽지 않는다.~~ **D-44로 대체.** 허기 0이면 작업 속도가 절반이 되고 궁핍 동기가 생기는 것은 그대로다 | |
| D-13 | 재산세(보유세)는 넣지 않는다 | 시뮬. 주 5%까지 걸어도 굶는 가구 수가 거의 안 줄었다. 세목이 늘면 탈세 처리도 는다 |
| D-14 | 과세 소득은 **순소득**이다(판매 + 봉급 + 집세 − 직업 재료·도구 구매) | 매출 기준이면 마진이 얇은 요리사가 망한다 |
| D-15 | 납부는 세금일에 광장으로 가서 한다. 못 간 가구는 다음 결산에서 자동 납부된다(낼 뜻이 있을 때) | 길 막힘으로 체납자가 되는 일을 막는다 |
| D-16 | 주민은 성별이 없다. 성년 독신이면 누구와도 혼인하고 출산한다 | 바닐라 주민과 같다 |
| D-17 | 혼인 물품 중 금 주괴는 소비되지 않고 예물로 남는다. 케이크와 음식은 소비된다 | 실물 원칙 |
| D-18 | 광산 조합의 몫: 광부 1.0, 갱도 보조 0.8, 관리자 1.2 | 구 기획의 건별 수수료보다 단순하다 |
| D-19 | 범행 문턱을 넘어도 매일 저지르지 않는다. 초과분에 비례한 확률로 저지른다 | 범죄 빈도 조절 |
| D-20 | 범죄 전용 직업은 없다. 겉 직업 + 범죄 숙련 + 조직 내 역할 6개 | 기획서 14.9 |
| D-21 | 약초사를 3물결에 넣는다. 금지 품목과 밀매, 횡령, 독 타기를 범죄 유형에 넣는다 | 기획서 14.9 |
| D-22 | 위조와 고리대는 9단계 뒤로 미룬다 | 사용자 결정 |
| D-23 | 발행, 세율 변경, 추방, 처형은 부관 규칙으로 못 한다 | 되돌릴 수 없거나 도시 전체를 흔든다 |
| D-24 | 시 레벨은 인구로 정하고 수용량(청크, 경비병, 부관, 규칙 줄)만 올린다. 정보는 정보 부관의 숙련으로 연다 | 사용자 확정 |
| D-25 | 의회는 표결 없이 권한 위임이다 | 사용자 확정 |

| D-27 | 밤을 건너뛰면(플레이어 수면) 휴식은 침대 유무로 바로 정하고, 밤에 계획된 행동은 추상 처리한다 | 불변식 6 |
| D-28 | 좀비에게 죽은 주민은 좀비 주민이 되지 않고 사망 처리한다 | 명부와 엔티티의 일대일 대응 유지 |

| D-31 | 조직의 돈은 계정이 아니라 은닉처 상자에 든 동화 아이템이다 | 실물 원칙. 시장이 상자를 열면 증거가 된다 |
| D-32 | CaG가 더하는 레시피는 양털 → 실 하나뿐이다 | 낚싯대와 활의 실을 닫힌 경제 안에서 대려면 필요하다 |
| D-33 | 놓는 사치품(양탄자, 그림 등)은 자가에서만 놓는다 | 집을 사는 이유를 만든다. 임대주택의 블록 소유 문제를 피한다 |
| D-34 | 구역 태그는 코드에서 전부 등록한다. 직업 JSON은 등록된 태그만 가리킨다 | Lib의 태그 그룹은 모드 초기화 때 정해진다 |
| D-35 | 2단계에서만 "아무 컨테이너에서나 값 없이 가져다 쓴다"는 임시 규칙을 쓰고 3단계에서 없앤다 | 시장 없이 직업 행동만 먼저 검증하기 위해 |
| D-36 | 주민은 순간이동하지 않는다. 길이 막히면 그날 그 일을 포기하고 진단 문구를 남긴다. 구매·납부만 추상 처리로 보완한다 | 플레이어가 길 문제를 보고 고칠 수 있어야 한다 |
| D-37 | 호가 = 기준가 × P × 배수. 매물마다 배수 하나만 움직이고, 범위는 0.5~2.0 | 사용자 제안. 계산이 싸고 상한이 생긴다 |
| D-38 | 기준가는 노동 시간으로 계산한다. 개발 도구가 직업 자료에서 `item_values.json` 을 만든다 | 손으로 잡은 표에서는 철 도구가 주간 소득보다 비쌌다 |
| D-39 | P는 가구별 1인당 지갑의 **중앙값**으로 잡는다 | 시뮬 2판. 평균이면 수매를 발행으로 메울 때 물가가 6.9배가 됐다 |
| D-40 | 내구재는 **주문 생산**이다. 선금 50%. 소모품은 소량 재고 생산 | 사용자 제안. 장인의 선지출과 안 팔리는 재고를 없앤다 |
| D-41 | 작업자는 필수 도구의 예비품 1개를 사물함에 둔다 | 사용자 제안. 시뮬에서 효과는 확인하지 못했다(막힌 곳이 도구 값이었다) |
| D-42 | 여윳돈은 욕구가 찼는지와 무관하게 쓴다 | 시뮬 2판. 굶는 가구 12.3 → 2.2. 가장 효과가 큰 규칙 |
| D-43 | **시 수매:** 금고가 하한가로 잉여를 산다. 잉여분만, 가구별 한도, 식량은 다시 방출. "잉여 매입 폐기"(1판)를 뒤집는다 | 사용자 제안 + 시뮬 2판. 조건 없이 사면 식량이 창고로 빨려 들어가 오히려 굶었다 |
| D-44 | **아사:** 허기 0이 5일 이어지면 죽는다. 영입·출생 뒤 28일은 유예 | 시뮬 2판. 관리되는 도시에서는 정착 뒤 거의 일어나지 않아, 방치의 신호로 쓸 수 있다 |
| D-45 | **사물함** 블록을 둔다. 작업함은 사물함만 되고, 구역 정원은 사물함 수를 넘지 못한다 | 사용자 지시. 자리와 소유가 눈에 보인다 |
| D-46 | **지도 테이블** 블록을 둔다. 지형과 구역을 색으로만 그린 평면 지도, 지형은 수동 갱신, 붙이면 커진다 | 사용자 지시. 입체 지도(L6)를 대신한다 |
| D-47 | **금고**는 3×3×3의 다중 블록이다(조립법은 D-54). 인출·입금·수매·방출은 금고에서만 한다. 금고 잔고 자체는 도시 자료의 숫자다 | 사용자 지시 |
| D-48 | 갱도 표지 블록은 만들지 않는다. 귀환 시각은 광산 계획의 통로 그래프로 계산한다 | 블록에 기대면 블록이 없어질 때 계산이 깨진다 |
| D-49 | 사물함과 금고에는 호퍼 같은 자동화가 붙지 않는다 | 소유와 절취 판정을 지킨다 |
| D-50 | 폭동의 약탈 대상은 주 금고다. 문을 여는 데 시간이 걸린다. 금고가 없으면 광장 블록 | 경비병이 막을 시간을 준다 |
| D-51 | 수매 자금이 모자랄 때의 자동 발행은 정책 스위치이고 기본은 꺼짐이다. 부관 규칙으로는 못 바꾼다 | 발행은 시장의 결정이다(D-23) |
| D-52 | 금고 내부 정리는 자체 구현한다 | 구리 골렘은 1.21.1에 없다 |
| D-53 | 영입은 동화 아이템 없이 Shift+우클릭으로 한다. 주민에게 돈을 건네는 것도 화면에서 금고 잔고로 바로 된다 | 금고 블록을 짓기 전에는 동화 아이템을 꺼낼 수 없다 |
| D-54 | 금고 블록의 제작법은 철 주괴 8개(가운데 빈 고리). 금고 블록 하나를 철 블록 26개로 감싸면 금고로 변하고 이어진 텍스처가 씌워진다. D-47의 "금고 블록 27개"를 고친다 | 사용자 지시. 처음부터 시장이 돌 필요는 없다 |
