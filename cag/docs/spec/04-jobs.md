# 04. 직업

## 1. 직업 정의 형식

데이터팩 `data/<ns>/cag/jobs/<id>.json`. 모드 조건이 맞을 때만 읽는다.

```json
{
  "requires_mods": [],
  "family": "farming",
  "zone_tag": "field",
  "capacity": { "type": "area", "cells_per_worker": 48 },
  "tools": [ { "kind": "hoe", "required": true } ],
  "tasks": [
    { "task": "till_plant", "priority": 2, "params": { "crops": ["wheat","carrots","potatoes","beetroots"] } },
    { "task": "harvest_crop", "priority": 1 }
  ],
  "recipes": [],
  "sells": ["minecraft:wheat","minecraft:carrot","minecraft:potato","minecraft:beetroot"],
  "throughput": { "minecraft:wheat": { "per_day": 30, "time_share": 0.6 }, "minecraft:carrot": { "per_day": 14, "time_share": 0.4 } },
  "income_hint": 12,
  "map_color": "#B8C46A",
  "skin": "farmer",
  "wave": 1
}
```

| 필드 | 뜻 |
|---|---|
| `family` | 계열. 같은 계열 안에서 이직하면 새 직업 경험치 = max(기존 값, 옛 직업 경험치의 절반) |
| `zone_tag` | 이 직업의 작업구역 태그. 공직은 없다 |
| `capacity` | 정원 식. `area`(면적 ÷ 값), `station`(구역 안 지정 블록 수 × 값), `fixed`. **실제 정원 = min(이 식, 그 구역의 사물함 수)** |
| `tools` | 도구 종류. `required` 가 참이면 없을 때 그 작업을 못 한다 |
| `tasks` | 작업 기본 동작과 우선순위(작은 수가 먼저) |
| `recipes` | 제작·제련할 바닐라 레시피 id 목록 |
| `sells` | 매물로 내놓는 품목 |
| `throughput` | 품목별 하루 산출과 시간몫. 기준가 산정에 쓴다(`03-economy.md` 2절). 3단계에서 재서 넣는다 |
| `income_hint` | 종사자가 없을 때 쓰는 하루 소득 추정(P = 1 기준) |
| `map_color` | 지도 테이블에서 이 직종 구역의 색 |
| `skin` | 바닐라 주민 직업 옷 텍스처 이름 |
| `wave` | 구현 물결 |

## 2. 작업의 공통 규칙

- 결산 11단계에서 주민마다 오늘의 작업 대기열을 만든다. 작업 구간(오전·오후)에 앞에서부터 한다.
- 작업 한 번의 흐름: 대상 칸 고르기 → 2블록 안으로 가기 → `시간` 틱 동안 팔 휘두르기 → 월드 변경 → 나온 아이템은 **바로 인벤토리로**(바닥에 떨어뜨리지 않는다).
- 인벤토리가 `§job.deposit_stacks` 묶음 이상 차거나 구간이 끝나면 사물함에 넣는다.
- 같은 구역의 주민끼리는 칸을 예약해서 같은 칸을 두 번 잡지 않는다.
- **시간:** 기본 시간 × 도구 등급 배수 ÷ 숙련 속도 배수. 허기 0이면 × 2, 휴식 30 미만이면 ÷ 0.7, 노년이면 ÷ `§life.elder_work_mult`.

| 도구 등급 | 배수 |
|---|---|
| 필요한데 없음 | 그 작업 불가 |
| 나무 | 1.6 |
| 돌 | 1.3 |
| 철 | 1.0 |
| 다이아몬드 | 0.8 |
| 효율 마법부여 | 등급당 −10% |

- **도구 소모:** 작업 한 번마다 `§job.tool_wear_scale` × 숙련 소모 배수의 확률로 내구도 1. 내구성 마법부여는 바닐라 식대로.
- **예비 도구:** 필수 도구마다 쓰는 것 1개와 예비 `§job.spare_tools` 개를 사물함에 두려 한다. 모자라면 그날 주문한다(`03-economy.md` 7절). 일을 시작할 때 사물함에서 꺼내 들고 끝나면 넣는다.
- 쓸 도구가 하나도 없는 채 `§job.no_tool_days` 가 지나면 물자 요청이 올라간다.
- **경험치:** 작업 한 번에 1, 제작 한 번에 2.
- **쉬기:** `03-economy.md` 5절의 생산 쉬기 규칙에 걸린 품목의 작업은 대기열에 넣지 않는다.

- **설비는 시장이 놓는다.** 사물함, 작업대, 화로, 모루, 베틀, 독서대, 퇴비통, 벌통, 양조기는 작업구역 안에 있어야 한다. 사물함이나 필수 설비가 없으면 정원이 0이다.

- 밭 작물 "자동": 씨앗이 있는 작물 중 `최저 호가 ÷ 기준값` 이 가장 높은 것을 심는다.
- 유리병을 만드는 직업은 없다. 꿀병은 양봉가의 사물함에 병이 있을 때만 만든다(병은 시장이 댄다). 없으면 벌집 조각과 꽃만 판다.

## 5. 숙련

| 등급 | 이름 | 경험치 | 속도 배수 | 도구 소모 배수 | 덤 산출 확률 |
|---|---|---|---|---|---|
| 1 | 초보 | 0 | 1.00 | 1.00 | 0 |
| 2 | 견습 | `§skill.xp2` | 1.15 | 0.95 | 5% |
| 3 | 숙련 | `§skill.xp3` | 1.30 | 0.90 | 10% |
| 4 | 전문 | `§skill.xp4` | 1.45 | 0.85 | 15% |
| 5 | 장인 | `§skill.xp5` | 1.60 | 0.80 | 20% |

- 덤 산출: 1차 생산 작업에서 산출물이 하나 더 나온다. 제작 직업에는 없다.
- **전문성 투자**(TOOL 칸으로 산다):
  - 더 좋은 등급의 도구.
  - 직업 서적: 읽으면 그 직업 경험치 + `§skill.book_xp`. `§skill.book_cooldown_days` 에 한 권. 소모된다.
  - 마법부여 책: 효율 또는 내구성. 산 주민이 자기 도구에 바로 바른다(모루 과정은 생략).

## 6. 서비스형 작업

### 수리 (`repair`)
- 도구 내구도가 30% 미만인 주민은 장보기 목록에 "수리"를 올린다. 새 도구 값과 수리비 중 싼 쪽을 고른다.
- 수리비 = 그 도구 재료 주괴의 호가 × 주괴 개수 × 닳은 비율 × `§job.repair_markup`.
- 손님이 대장간 사물함 3블록 안으로 오면 거래한다. 대장장이 사물함의 주괴가 `개수 × 닳은 비율`(올림)만큼 줄고 도구가 다 고쳐진다. 대장장이는 다음 작업으로 `repair` 한 번을 한다(시간 소모).
- 주괴가 없으면 수리 매물이 없다.

### 책 (`write_book`)
- 직업 서적: 책 1 → `job_book`(직업 지정). 어떤 직업 것을 쓸지는 그 직업 종사자 수에 비례해 고른다.
- 마법부여 책: 책 1 + 청금석 3 → 효율 또는 내구성. 등급은 사서 숙련 1~2면 I, 3~4면 II, 5면 III.

### 치료 (약초사)
- 다쳤거나 앓는 주민(`injuredUntil`, `sickUntil`)은 재생 효과의 수상한 스튜를 산다. 먹으면 남은 기간이 절반이 된다.
- 꽃과 효과의 대응은 바닐라의 수상한 스튜 표를 그대로 쓴다. 구현 때 1.21.1의 표를 확인한다.
- 독·실명·약화 스튜와 물약의 쓰임은 `05-crime.md`.

## 7. 상인 (`trade_route`)

- 가게 구역의 사물함이 상인의 판매함이다.
- 상인은 재고 생산 품목만 다룬다. 주문 생산 품목은 손님이 만드는 사람에게 직접 주문한다.
- **매입:** 품목마다 가게 재고가 목표(판매 평활 × `§price.target_days`)보다 적으면, 생산자 매물 중 호가가 가장 낮은 것을 사 온다. 다른 상인의 매물은 사지 않는다.
- **취급 품목:** 처음에는 도시에서 전날 거래가 있었던 품목 전부. 3일 연속 안 팔린 품목은 `§merchant.drop_days` 동안 매입하지 않는다.
- **호가:** `03-economy.md` 5절 규칙을 쓰되 하한의 재료비 자리에 `매입 단가 × (1 + §merchant.markup)` 을 넣는다.
- 손님이 상인을 고르는 이유는 거리와 구색이다(구매 점수의 거리 항).
- 상인의 과세 소득에서 매입비는 `businessCost` 다.

## 8. 광산

구 기획 "광부 설계"를 잇되 세 가지를 바꾼다: 광산 관리자를 더하고, 수입을 조합 몫으로 나누고, 지하 숙박을 뺀다.

### 구조
- 광산 구역은 지표에 칠한다. 광산은 **칠한 기둥의 아래**로만 자란다.
- 계획은 `MinePlan` 이 가진다: 주갱(계단), 층, 본갱, 가지갱, 조각 목록. 조각 하나 = 팔 칸, 횃불 자리, 막을 칸.
- 고정 패턴: 입구에서 내려가는 2칸 폭 계단 주갱 → 층마다 2칸 높이 본갱 → 본갱 양옆에 `§mine.branch_spacing` 칸 간격, 길이 `§mine.branch_length` 의 가지갱.
- 층 높이는 데이터 `mine_layers` 로 정한다. 기본은 Y 48(석탄·구리), 16(철), 0(청금석), −16(금), −54(다이아몬드·레드스톤). 바닐라 광석 분포에 맞춘 값이며 구현 때 1.21.1 분포로 확인한다.

### 확장
1. **조각 생성:** 현재 끝단이 `§mine.advance_ratio` 만큼 파이면 다음 조각(본갱 `§mine.segment_length` 칸 + 가지갱 한 쌍)을 만든다. 구역 기둥 밖으로는 만들지 않는다.
2. **사전 검사:** 조각의 칸과 바깥 한 칸을 훑는다.
   - 용암·물 → 막을 칸으로 표시. 조각의 30% 넘게 걸리면 그 조각을 버리고 반대쪽으로 낸다.
   - 뚫린 동굴 → 뚫린 면을 막을 칸으로.
   - 기반암, 컨테이너, 다른 구역의 칸 → 조각을 버린다.
   - 자갈·모래 → 떨어진 것까지 캔다.
3. **광맥 따라 파기:** 벽에 광석이 보이면 이어진 광석을 `§mine.vein_max` 칸까지 캔다. 광석 칸만 판다.
4. **층 고르기:** `최저 호가 ÷ 기준값` 이 가장 높은 광물의 층을 먼저 넓힌다. 그 층이 없으면 주갱을 더 내린다.
5. **소진:** 구역 아래에 더 낼 조각이 없으면 보이는 광석을 다 캔 뒤 닫는다. 진척이 `§mine.exhaust_warn` 을 넘으면 "새 광산 부지" 요청을 올린다.

### 역할과 정원
| 상태 | 광부 정원 | 일하는 법 |
|---|---|---|
| 관리자 없음 | `§mine.miners_no_manager` | 끝단 하나를 같이 판다. 횃불·막기·운반도 광부가 한다 |
| 관리자 있음 | 열린 층 수 × `§mine.miners_per_layer` | 관리자가 광부를 층에 나눠 배치하고 층 고르기를 한다 |

- 갱도 보조 정원 = 광부 수 ÷ 2(올림). 보조가 있으면 광부는 파기만 한다.
- 보조의 우선순위: 막기 → 횃불(간격 `§mine.torch_spacing`) → 운반.
- 광부는 막기가 끝난 조각만 판다. 파다가 용암·물이 새로 드러나면 그 칸을 조약돌로 막고 조각에 표시한다.
- 관리자는 광산 입구의 조합 수납함 곁에서 일한다: 층 배치, 조합 수납함의 판매, 몫 나누기.

### 조합 (D-18)
- 광산 구역의 사물함 중 입구에서 가장 가까운 것이 조합 사물함(`MINE_COOP`)이 된다. 캔 것은 전부 여기 모인다. 나머지 사물함은 광부·보조·관리자 각자의 것으로, 도구와 예비품을 둔다.
- 매물의 판매자는 관리자(없으면 가장 먼저 배정된 광부)다. 판 돈은 조합 계정에 쌓인다.
- 결산 4단계에서 전날 조합 수입을 몫으로 나눈다. 몫: 광부 1.0, 갱도 보조 0.8, 관리자 1.2. 전날 근무 비율이 0.5 미만인 사람은 몫이 없다.
- 받은 돈은 `COOP_SHARE` 로 각 가구에 가고 `wages` 로 과세된다. 도구와 횃불 구매는 각자의 `businessCost` 다.
- **횡령:** 관리자가 나누기 전에 일부를 빼돌릴 수 있다(`05-crime.md` 4절).

### 이동과 안전
- 지하 숙박은 없다. 매일 출퇴근한다(D-30).
- **귀환 시각:** 블록 표지 없이 `MinePlan` 의 통로 그래프로 계산한다(D-48).
```
입구까지 거리 = 지금 있는 조각에서 입구까지의 그래프 거리(조각을 만들 때 계산해 조각에 적어 둔다)
귀환 시작 = 구간 끝 시각 − 입구까지 거리 ÷ 걷는 속도 × §mine.return_margin
```
  오전 구간이 끝날 때는 올라오지 않고 그 자리에서 쉰다. 오후 구간의 끝에만 귀환한다.
  광산이 깊어질수록 오가는 시간이 늘어 실제 작업 시간이 준다. 작업 시간이 하루의 `§mine.min_work_ratio` 밑으로 내려가면 관리자(없으면 광부)가 "새 광산 부지" 요청을 올린다.
- 먼 이동은 `MinePlan` 의 통로 그래프로 경유지를 잡고, 바닐라 경로 탐색은 경유지 사이에만 쓴다.
- 횃불 간격을 지키면 갱도 안에 몹이 생기지 않는다. 몹이 다가오면 지상으로 달아난다.
- 레일과 광차 출퇴근은 9단계 뒤의 선택 기능이다.

### 광산의 구현 순서
| 단계 | 내용 | 개발 단계 |
|---|---|---|
| M1 | 구역, 주갱과 첫 층, 고정 패턴, 사전 검사, 광맥 따라 파기, 광부 혼자 전부 | 4 |
| M2 | 조합 수납함과 몫, 갱도 보조, 광산 관리자, 여러 층 | 5 |
| M3 | 레일 | 9 이후 |

## 9. 배정과 이직

### 배정
- 시장(또는 부관)이 주민을 작업구역에 배정하면 그 구역 태그의 직업을 갖는다. 정원이 차 있으면 못 한다.
- 배정되면 그 구역의 주인 없는 사물함 하나를 잡고, 다음 결산부터 작업 대기열이 생긴다. 빈 사물함이 없으면 배정되지 않는다.
- 주민은 어떤 배정이든 받아들인다. 원하던 직업이 아니면 성취의 "선호"가 0이 되고 나중에 이직 요청을 올린다.

### 무직자의 희망 직업
결산 7단계에서, 대기 중인 요청이 없는 무직 성인마다:
```
점수(직업) = 소득 지수(직업) × (선호 직업이면 §jobchange.preferred_mult, 아니면 1)
소득 지수  = 그 직업 종사자들의 최근 7일 순소득 평균. 종사자가 없으면 income_hint × 7 × P
```
점수가 가장 높은 직업으로 "일터" 요청을 올린다. 공직은 희망 직업이 되지 않는다.

### 이직 요청
쿨다운이 지난 취업 성인이 아래 중 하나에 해당하면 올린다.
- 현재 직업이 선호 직업이 아니고, 선호 직업 중 정의된 것이 있다.
- 자기 가구의 7일 순소득 < `§jobchange.income_ratio` × (빈자리가 있는 직업 중 최고 소득 지수)인 주가 `§jobchange.poor_weeks` 주 이어졌다.

반려되거나 만료되면 `§jobchange.cooldown_days` 동안 다시 올리지 않고, 성취 −10, `requestScore` −5.

수락되면 옛 사물함을 풀고(남은 물건은 집으로 나른다) 새 구역에 배정된다. 경험치는 1절의 계열 규칙을 따른다.
